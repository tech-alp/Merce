# Phase 04 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Phase UI Boundary

Phase 4 does not need a visible production UI. UI work is constrained to a focused QML probe plus an optional minimal playground selector used to prove runtime brand/mode switching.

Do not build a marketing page, theme gallery, screenshot gallery, broad component matrix, or decorative card-heavy preview. Phase 5 owns gallery-level visualization and screenshot automation.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none |
| Preset | not applicable |
| Component library | Merce Qt/QML components (`Merce.Core`, `Merce.Foundation`, `Merce.Controls`) |
| Icon library | existing Merce iconography tokens only; no new icon dependency |
| Font | `Theme.typography.fontBody` for probe/playground controls; resolved from active manifest |

Design source of truth is the existing C++ `Merce.Core.Theme` singleton. New QML for this phase must consume `Theme.palette`, `Theme.spacing`, `Theme.radius`, and `Theme.typography`; it must not hard-code visual colors except in assertions inside focused probes.

shadcn gate: not applicable because this is a Qt 6/QML/CMake project, not React/Next.js/Vite. No `components.json`, Tailwind config, or postcss config is present.

## Runtime Switch Contract

| State / Request | Expected Behavior | Visible Probe / Playground Contract |
|-----------------|-------------------|-------------------------------------|
| Default startup | Apply registry default `merce/light`. | Probe can assert `Theme.activeBrand == "merce"`, `Theme.activeMode == "light"`, and `Theme.palette.backgroundBase == "#FAF8F6"` after Phase 4 API exists. |
| `Theme.setTheme("merce", "dark")` | Return `true`; update active state to `merce/dark`; update semantic values in stable sub-objects. | Bound UI background/text/action/border values must repaint without recreating the QML scene. |
| `Theme.setTheme("merce", "light")` | Return `true`; update active state to `merce/light`. | Selector marks Light as active and Dark as inactive if selector exists. |
| `Theme.setTheme("stripe")` | Return `true`; update active brand to `stripe`; active mode is empty string. | Mode control is disabled or hidden for Stripe. Do not fabricate a `light` mode label. |
| Unknown brand or mode | Return `false`; preserve active state and applied values; log clearly. | Optional selector keeps previous selection; show short inline error text only if a manual selector is present. |
| Registered broken manifest with fallback | Apply loader result if valid fallback is returned; active state reflects actual applied fallback, not requested broken state. | Probe asserts actual active brand/mode after fallback if such fixture is used. |

Public QML terminology is locked as `brand` and `mode`: `Theme.setTheme(brand, mode)`, `Theme.activeBrand`, `Theme.activeMode`. Internal implementation may keep `theme` and `variant`.

Do not add QML-visible diagnostics such as `Theme.lastError` or `Theme.usedFallback` in Phase 4.

## Optional Playground Selector

Only add this if it helps manual verification in `playground/Main.qml`; the focused QML probe remains the required UI proof.

| Control | Contract |
|---------|----------|
| Brand control | Use clear brand options: `Merce`, `Stripe Reference`. Minimum target height: `Theme.spacing.touchTarget` (44px). |
| Mode control | Use `Light` and `Dark` only for `Merce`; disable or hide the mode control for `Stripe Reference`. |
| Apply action | Single primary action labeled `Temayı uygula`; call `Theme.setTheme(selectedBrand, selectedMode)`. |
| Active state | Selected brand/mode controls must visually use `Theme.palette.actionPrimary` and `Theme.palette.border.focus`; inactive controls use semantic surface/border tokens. |
| Invalid state | Keep previous visual selection and show `Tema uygulanamadı.` only when a manual action fails. |
| Layout | One compact row or column near the top of the playground content. Do not add nested cards, a gallery, screenshots, or explanatory tutorial copy. |

Primary visual anchor is the active brand/mode selector row; eye priority is active selection, then apply action, then inline status.

Selector controls must be built from existing Merce QML components or plain QtQuick primitives using Merce tokens. No new third-party dependency is allowed.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xxs | 4px | Tight glyph/control gaps, focus inset offsets |
| xs | 8px | Inline gaps inside compact controls |
| sm | 8px | Label-to-control spacing |
| md | 16px | Default control groups and probe row gaps |
| lg | 24px | Compact section padding inside optional selector |
| xl | 24px | Playground page padding and row grouping |
| 2xl | 32px | Major playground gaps, selector block separation |
| 4xl | 48px | Existing section gap; avoid adding new Phase 4 sections |
| 5xl | 64px | Page-level spacing only; normally unused in Phase 4 |

Exceptions: `Theme.spacing.touchTarget` is 44px for kiosk-friendly controls; `Theme.spacing.touchTargetCompact` is 36px for secondary compact controls that are not primary mode/brand choices.

## Typography

Use exactly these text roles for new Phase 4 probe/playground UI:

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | `Theme.typography.sizeMedium` (16px) | `Theme.typography.weightRegular` (400) | `Theme.typography.leadingNormal` (1.5) |
| Label | `Theme.typography.sizeSmall` (14px) | `Theme.typography.weightSemibold` (600) | `Theme.typography.leadingTight` (1.2) |
| Heading | `Theme.typography.sizeXLarge` (20px) | `Theme.typography.weightSemibold` (600) | `Theme.typography.leadingSnug` (1.35) |
| Status | `Theme.typography.sizeXSmall` (12px) | `Theme.typography.weightRegular` (400) | `Theme.typography.leadingNormal` (1.5) |

No new display-scale hero typography is allowed in Phase 4. Font families must come from `Theme.typography.fontBody`; do not hard-code `DM Sans` in visible UI.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `Theme.palette.backgroundBase` (`#FAF8F6` light, `#1F1510` dark, `#F6F9FC` stripe) | Window/page background and unfocused probe area |
| Secondary (30%) | `Theme.palette.backgroundSurface` / `Theme.palette.background.elevated` (`#FFFFFF` light/stripe, `#2A211C` / `#342923` dark) | Optional selector surface, dropdown/menu body, neutral control backgrounds |
| Accent (10%) | `Theme.palette.actionPrimary` (`#C4785A` merce, `#635BFF` stripe) | Active brand/mode selection, primary apply action, focused border, link/action emphasis |
| Destructive | `Theme.palette.status.error` (`#C45A5A`) | Invalid request text only; no destructive action is introduced |

Accent reserved for: active selected state, `Temayı uygula`, keyboard focus ring via `Theme.palette.border.focus`, and probe success/action emphasis. Do not use accent for body text, generic surfaces, decorative blocks, or every interactive element.

All visual changes between light/dark/single-manifest switching must come through semantic `Theme.palette` bindings. Do not set ad-hoc light/dark colors in playground UI.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | `Temayı uygula` |
| Empty state heading | `Kayıtlı tema yok` |
| Empty state body | `Tema listesi yüklenemedi. Varsayılan tema korunuyor.` |
| Error state | `Tema uygulanamadı. Geçerli marka ve modu seçin.` |
| Destructive confirmation | Yok; Phase 4 destructive action eklemez. |

Probe console output may stay terse: `theme-probe ok`, `theme-switch-probe ok`, `theme-switch-probe failed`. Visible playground copy must not explain how runtime switching works; it should only label controls and state outcomes.

## Accessibility And Interaction

| Requirement | Contract |
|-------------|----------|
| Touch target | Primary brand/mode/apply controls are at least 44px high. Compact secondary controls may be 36px only if not the main switch action. |
| Focus visibility | Focused controls use `Theme.palette.border.focus` with a 2px border or equivalent visible focus treatment in both light and dark. |
| Contrast | Text uses `Theme.palette.textPrimary` or `Theme.palette.text.secondary` on semantic backgrounds; disabled text uses the existing compatibility path `Theme.colors.text.disabled`. |
| Keyboard | Optional selector must be reachable by keyboard and must not require mouse-only interaction. |
| Disabled mode | Mode control for single-manifest brand is disabled or hidden; if visible, it must expose disabled state and not call `setTheme` with fabricated modes. |
| UI stability | Theme switch must not destroy/recreate the window, Flickable, page, or theme sub-object pointers. |
| Motion | Existing token-driven color transitions may remain; do not add new decorative animations for switching. |

## Verification Checkpoints

| Checkpoint | Required Proof |
|------------|----------------|
| Binding update | A QML bound property such as `property color observedBackground: Theme.palette.backgroundBase` changes after `Theme.setTheme("merce", "dark")`. |
| Pointer stability | `Theme.palette`, `Theme.spacing`, `Theme.radius`, and `Theme.typography` object pointers are the same before and after switching. |
| Active state | `Theme.activeBrand` and `Theme.activeMode` match actual applied result after light, dark, and Stripe selection. |
| Invalid request | Unknown brand/mode returns `false` and preserves active state plus observed semantic values. |
| No style-family switch | Phase 4 implementation does not call `QQuickStyle::setStyle`, edit `qtquickcontrols2.conf`, or add Qt Quick Controls style-family switching. |
| Probe scope | Use C++ QtTest plus focused QML probe. Spix, gallery screenshots, and full visual matrix are Phase 5. |

- No QML-visible diagnostics beyond `setTheme(...)` return value and active brand/mode properties.
