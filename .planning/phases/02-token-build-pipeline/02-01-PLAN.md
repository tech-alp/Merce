# Plan 01: Style Dictionary Token Build Pipeline

<objective>
Add a bounded Style Dictionary v5 build pipeline that reads DTCG source tokens, resolves a declared sparse theme/variant set, and emits versioned Merce runtime manifest JSON files without adding Node or generated token objects to Merce runtime or QML component APIs.

Decision coverage: D-01, D-02, D-03, D-04, D-05, D-06, D-07, D-08, D-09, D-10, D-11, D-12, D-13, D-14, D-15, D-16, D-17, D-18, D-19.
</objective>

<scope>
## In Scope

- Add a `tools/design-tokens` Node/npm workspace for Style Dictionary v5.
- Add DTCG source tokens for core values, a `merce` theme with `light` and `dark` variants, and a single-manifest `stripe` reference fixture.
- Add a declared sparse theme registry that does not force every theme to have dark/light variants.
- Add a custom Merce manifest formatter that emits runtime-shaped JSON.
- Generate `generated/themes/index.json`, `generated/themes/merce.light.json`, `generated/themes/merce.dark.json`, and `generated/themes/stripe.json`.
- Add manifest validation and deterministic output checking.
- Add optional CMake integration that is default-off and does not require Node for normal Qt builds.
- Document AI-assisted `DESIGN.md` to DTCG source generation.

## Out of Scope

- C++ manifest registry and loader.
- Qt resource packaging for generated manifests.
- Runtime `Theme.setTheme(theme, variant)` API.
- Runtime fallback behavior for missing or invalid manifests.
- Broad component migration from `Theme.colors.*` to `Theme.palette.*`.
- Public QML generated token files.
</scope>

<truths>
- D-01: The pipeline supports a declared sparse theme set, not a mandatory cartesian brand/mode matrix.
- D-02: Single-manifest themes must not receive a fake `defaultMode: light`.
- D-03: `variant` is the output/index term; `light` and `dark` are variant names only.
- D-04: Merge order must be explicit and deterministic.
- D-05: Style Dictionary emits Merce runtime manifests, not public QML token files.
- D-06: Manifest fields use shallow semantic names close to the C++ runtime API.
- D-07: Compatibility paths such as `colors.background.base` are not duplicated in manifest JSON.
- D-08: Manifest JSON includes schema/version and theme/variant identity.
- D-09: The generated index is authoritative for physical manifest paths.
- D-10: Style Dictionary tooling lives under `tools/design-tokens`.
- D-11: npm is build/developer tooling only.
- D-12: npm scripts should build and optionally clean/validate tokens.
- D-13: Generated manifests are committed or packaged so consumers do not need Node.
- D-14: AI may create DTCG source candidates from `awesome-design-md` references.
- D-15: AI must not create canonical final manifests directly.
- D-16: Real reference names such as Stripe may be used for fixture theme names.
- D-17: Phase 2 includes schema/version validation.
- D-18: Phase 2 includes deterministic output checks.
- D-19: Phase 3 owns runtime loader/fallback behavior.
</truths>

<must_haves>
- All `TOKENS-01` through `TOKENS-05` requirement IDs are covered by this plan.
- `tools/design-tokens/package.json` declares Node `>=22.0.0`.
- DTCG source files use `$value` and `$type`; do not mix legacy `value`/`type` in the same token source set.
- `generated/themes/index.json` has no `defaultMode` field for single-manifest themes.
- `generated/themes/stripe.json` exists as a single-manifest theme.
- `generated/themes/merce.light.json` and `generated/themes/merce.dark.json` exist as variant manifests.
- Generated manifests contain semantic sections such as `palette`, `spacing`, `radius`, and `typography`.
- Generated manifests do not contain public compatibility sections named `colors`.
- Normal CMake configure/build does not require Node unless the optional token target is explicitly enabled.
</must_haves>

<threat_model>
## Threat Model

### T-01: Untrusted DESIGN.md or AI output injects invalid tokens
- Severity: medium
- Mitigation: AI output is reviewed DTCG source only. The build validates generated manifests and never treats AI output as canonical final manifest JSON.

### T-02: Node/Style Dictionary leaks into Merce runtime dependency chain
- Severity: high
- Mitigation: Keep all npm files under `tools/design-tokens`; make CMake token target optional/default-off; commit or package generated manifests.

### T-03: Generated manifest shape drifts from C++ runtime API
- Severity: medium
- Mitigation: Use a custom formatter with explicit field mapping and a validation script that checks required semantic sections and schema version.

### T-04: Missing variant is silently fabricated
- Severity: medium
- Mitigation: Use sparse registry semantics. Build only paths declared in `themes.json`; never generate missing `light` or `dark` variants automatically.
</threat_model>
