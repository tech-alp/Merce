# Phase 05 - UI Design Contract

> Visual and interaction contract for the verification gallery phase. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Phase UI Boundary

Phase 5 adds a verification-oriented playground gallery for Merce theme runtime evidence. The gallery exists to make runtime theme values, component consumption, and exported visual artifacts easy to inspect.

This phase must not create a marketing page, landing page, tutorial screen, broad component-state matrix, new public theme runtime API, raw generated-token API, Spix dependency, or Qt Quick Controls style-family switching.

Primary visual anchor: the active brand/mode readout and gallery selector row at the top of `ThemeGallery.qml`.

Visual hierarchy:

1. Active brand/mode state and selector.
2. Palette swatches for canonical `Theme.palette` values.
3. Typography, spacing, and radius samples.
4. Representative component states.
5. Export/readme evidence status.

The UI should feel like a compact design-system verification surface, not a product landing page. Use full-width playground sections inside the existing scroll surface; do not nest cards inside cards.

## Design System

| Property | Value |
|----------|-------|
| Tool | none |
| Preset | not applicable |
| Component library | Merce Qt/QML components (`Merce.Core`, `Merce.Foundation`, `Merce.Controls`, `Merce.Notifications`) |
| Icon library | existing Merce iconography tokens only; no new icon dependency |
| Font | `Theme.typography.fontBody` for normal text; `Theme.typography.fontDisplay` only for the gallery title if the existing `MText` preset uses it |

Design source of truth is the C++ `Merce.Core.Theme` singleton. New gallery/probe UI must prefer canonical paths: `Theme.palette`, `Theme.iconography`, and `Theme.breakpoints`. Existing component internals may continue using compatibility aliases such as `Theme.colors` and `Theme.icons`; Phase 5 must not broaden alias cleanup beyond files it already touches for gallery/probe/smoke work.

shadcn gate: not applicable because this is a Qt 6/QML/CMake project, not React/Next.js/Vite. No `components.json`, Tailwind config, or postcss config is present.

## Gallery Screen Contract

| Area | Contract |
|------|----------|
| Root | `ThemeGallery.qml` root objectName is `merce.playground.gallery`; it is registered in `playground/CMakeLists.txt` and integrated from `playground/Main.qml`. |
| Active theme | Show `Theme.activeBrand` and `Theme.activeMode`. Empty mode for `stripe` is displayed as `default`, not as fabricated `light`. |
| Selector | Provide compact brand/mode controls for `Merce Light`, `Merce Dark`, and `Stripe Reference`. Controls call `Theme.setTheme(brand, mode)` and keep previous active state if the call fails. |
| Palette | Use canonical `Theme.palette` labels and swatches for background, text, action, border, and status colors. Do not show alias families such as `colors` as separate tokens. |
| Typography | Show body, label, heading, and gallery title samples using `Theme.typography` values. Do not introduce hero-scale marketing type. |
| Spacing/radius | Show scale bars or chips for the declared layout scale and radius samples for button, input, and card/dialog shapes. |
| Components | Include representative controls already in the playground: `MButton` variants, `MText`, `MInput`, `MCheckbox`, `MRadio`, `MSwitch`, `MSelect`, `MToast`, and `MDialog`. |
| Export evidence | Provide a deterministic gallery export route or command that writes README-ready visual artifacts. The visible UI only needs concise status text; do not include instructions in the app surface. |

Required stable object names:

| Element | objectName |
|---------|------------|
| Gallery root | `merce.playground.gallery` |
| Active theme area | `merce.playground.gallery.activeTheme` |
| Palette section | `merce.playground.gallery.palette` |
| Typography section | `merce.playground.gallery.typography` |
| Spacing/radius section | `merce.playground.gallery.spacingRadius` |
| Components section | `merce.playground.gallery.components` |
| Export status | `merce.playground.gallery.exportStatus` |

Optional qmlagent inspection must target authored `objectName` selectors, not generated node ids.

## Spacing Scale

Declared layout values for new gallery structure:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Swatch label gaps, focus inset offsets |
| sm | 8px | Inline gaps inside compact controls |
| md | 16px | Default item spacing, component group gaps |
| lg | 24px | Gallery section padding |
| xl | 32px | Section-to-section spacing |
| 2xl | 48px | Major gallery breaks and screenshot framing margins |
| 3xl | 64px | Page-level bottom padding only |

Exceptions: existing Merce control-size tokens remain valid: `Theme.spacing.touchTarget` is 44px and `Theme.spacing.touchTargetCompact` is 36px. These are touch target heights, not layout spacing values. New gallery layout spacing must use the declared table above.

## Typography

Use exactly these text roles for new Phase 5 gallery UI:

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | `Theme.typography.sizeMedium` (16px) | `Theme.typography.weightRegular` (400) | `Theme.typography.leadingNormal` (1.5) |
| Label | `Theme.typography.sizeSmall` (14px) | `Theme.typography.weightSemibold` (600) | `Theme.typography.leadingTight` (1.2) |
| Heading | `Theme.typography.sizeXLarge` (20px) | `Theme.typography.weightSemibold` (600) | `Theme.typography.leadingSnug` (1.35) |
| Gallery title | `Theme.typography.size3XLarge` (30px) | `Theme.typography.weightSemibold` (600) | `Theme.typography.leadingTight` (1.2) |

No new font family dependency is allowed. Do not hard-code `DM Sans` or platform fallback strings in visible QML; bind through `Theme.typography`.

Letter spacing for new visible text is 0. Do not use negative letter spacing in the gallery.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `Theme.palette.backgroundBase` (`#FAF8F6` light, `#1F1510` dark, `#F6F9FC` stripe) | Window/page background and gallery base |
| Secondary (30%) | `Theme.palette.backgroundSurface` / `Theme.palette.background.elevated` (`#FFFFFF` light/stripe, `#2A211C` / `#342923` dark) | Section surfaces, component sample backgrounds, export status surface |
| Accent (10%) | `Theme.palette.actionPrimary` (`#C4785A` Merce, `#635BFF` Stripe) | Active brand/mode selector, primary export action, focused border, selected swatch emphasis |
| Destructive | `Theme.palette.status.error` / `Theme.palette.statusError` (`#C45A5A`) | Destructive button sample only; no real destructive action is introduced |

Accent reserved for: active theme selection, `Tema galerisini dışa aktar`, keyboard/focus border via `Theme.palette.border.focus`, selected token emphasis, and link/action emphasis in visual evidence status. Do not use accent for body text, neutral surfaces, decorative blocks, every button, or every interactive element.

All visual changes between Merce light, Merce dark, and Stripe Reference must come through semantic `Theme.palette` bindings.

## Copywriting Contract

Visible app copy should be concise labels and state outcomes only. Do not explain how the feature works inside the playground.

| Element | Copy |
|---------|------|
| Primary CTA | `Tema galerisini dışa aktar` |
| Secondary action | `Temayı değiştir` |
| Empty state heading | `Galeri örneği yüklenemedi` |
| Empty state body | `Tema değerleri okunamadı. Varsayılan tema korunuyor ve doğrulama çıktısını kontrol edin.` |
| Error state | `Galeri dışa aktarılamadı. Hedef klasörü ve offscreen çalıştırma çıktısını kontrol edin.` |
| Success state | `Galeri görselleri hazır` |
| Destructive confirmation | Yok; Phase 5 gerçek destructive action eklemez. Destructive button yalnızca component state örneğidir. |

Probe/CLI output may stay terse and machine-checkable: `theme-probe ok`, `theme-switch-probe ok`, `theme-gallery-probe ok`, `theme-gallery-export ok`.

## Accessibility And Interaction

| Requirement | Contract |
|-------------|----------|
| Touch target | Selector and export controls are at least `Theme.spacing.touchTarget` (44px) high. Compact secondary controls may use 36px only when not the primary action. |
| Focus visibility | Focused selector/action controls use `Theme.palette.border.focus` with a 2px visible focus treatment in light, dark, and Stripe. |
| Contrast | Text uses `Theme.palette.textPrimary` or `Theme.palette.text.secondary` on semantic backgrounds. Disabled text may use the existing compatibility path if the component already does. |
| Keyboard | Selector controls and export action are keyboard reachable; no mouse-only interaction is required for the main gallery flow. |
| State preservation | Failed `Theme.setTheme(...)` calls keep the previous visual selection and active state. |
| Motion | Existing token-driven color/position transitions may remain. Do not add decorative animations or animated background effects. |
| Text fit | Labels inside controls must fit at desktop width 1100px and at narrow/mobile-like widths; wrap section labels if needed rather than shrinking by viewport width. |

## Visual Evidence Contract

| Artifact | Contract |
|----------|----------|
| Merce light | Export one README-ready image after default `merce/light` is active. |
| Merce dark | Export one README-ready image after `Theme.setTheme("merce", "dark")` succeeds. |
| Stripe Reference | Export one README-ready image after `Theme.setTheme("stripe")` succeeds with empty active mode. |
| Output path | Use a deterministic repo-relative path such as `docs/assets/theme-gallery/` or `playground/artifacts/theme-gallery/`; planner must choose one path and keep it consistent in README/docs. |
| Required proof | Offscreen export command exits 0 and writes non-empty image files. Pixel-perfect visual diff is not required in Phase 5. |

README/docs must include the exact command used to generate the artifacts. The app UI itself must not show command tutorials.

## Verification Checkpoints

| Checkpoint | Required Proof |
|------------|----------------|
| Probe values | `MercePlayground --theme-probe` verifies known public runtime values through canonical `Theme.palette`, spacing, radius, typography, and iconography access. |
| Runtime switch | `MercePlayground --theme-switch-probe` verifies light, dark, Stripe, invalid request preservation, and stable sub-object pointers. |
| Gallery smoke | `MercePlayground --smoke-test` loads `Main.qml` with `ThemeGallery.qml` integrated. |
| Gallery probe | A focused gallery route or probe proves required gallery object names exist and active theme state is visible. |
| Export | A deterministic offscreen export command writes non-empty README-ready images for Merce light, Merce dark, and Stripe Reference if practical. |
| Component consumption | Representative controls repaint after at least one theme switch because they consume the active runtime theme through `Theme`. |

Mandatory verification remains local and deterministic: QtTest/CTest plus offscreen playground probe/smoke/gallery execution. qmlagent inspection is optional.
