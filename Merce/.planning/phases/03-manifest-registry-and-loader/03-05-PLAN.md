<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| validated manifest -> QObject storage | Manifest values mutate QML-visible theme properties. |
| loader failure -> construction defaults | Broken default manifests must be visible through logs, not silent success. |
| C++ internals -> QML public API | Phase 3 must not expose switching or diagnostics to QML. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-05-01 | Tampering | supported theme object apply methods | mitigate | Apply only after loader validation and assign complete supported sections; no field-by-field fallback from construction values. |
| T-03-05-02 | Repudiation | default load failure | mitigate | Log clear warnings when loadDefault fails and keep construction defaults without reporting ok=true. |
| T-03-05-03 | Information Disclosure | QML diagnostics | mitigate | Do not add Theme.lastError, usedFallback, activeTheme, activeVariant, or public loader state in Phase 3. |
| T-03-05-04 | Denial of Service | QML binding updates | mitigate | Preserve NOTIFY signals and emit section changed signals only around successful apply so bindings remain valid. |
| T-03-05-05 | Supply Chain | runtime dependency confusion | accept | Runtime apply uses the Qt Core loader from Plan 04 and introduces no package-manager dependency. |
</threat_model>
