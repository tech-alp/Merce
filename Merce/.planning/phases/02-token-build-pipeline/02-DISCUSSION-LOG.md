## Token Layer Düzeni

| Option | Description | Selected |
|--------|-------------|----------|
| Minimal layers | Core, default brand, light/dark mode iskeleti kurulur; sadece default light/dark üretilir. | |
| Full matrix | Birden fazla brand/mode kombinasyonu baştan pipeline kapsamına alınır. | yes |
| Flat source | Tek default token kaynağıyla başlanır; layer modeli sonra eklenir. | |

**User's choice:** Full matrix.
**Notes:** The user asked where the complexity comes from. The discussion clarified that complexity is in deterministic merge order, required fields per declared theme/variant entry, fallback behavior, output naming, and snapshot validation. The locked interpretation was later refined: do not require every brand/theme to support every dark/light mode.

## Manifest Şeması

| Option | Description | Selected |
|--------|-------------|----------|
| Runtime API semantic schema | Manifest runtime API'ye yakın shallow semantic alanlar üretir. | yes |
| Dual schema | Manifest hem yeni shallow alanları hem eski compatibility shape'i taşır. | |

**Notes:** The manifest was explained as the intermediate JSON generated by Style Dictionary and consumed by the future C++ runtime loader. The user selected the runtime-shaped manifest approach.

## AI-Assisted Brand Fixtures

| Option | Description | Selected |
|--------|-------------|----------|
| AI seed, DTCG source | AI `DESIGN.md` okuyup DTCG source üretir; Style Dictionary manifest üretir. | yes |
| AI direct manifest | AI doğrudan resolved manifest üretir. | |
| Manual only | Brand token dosyaları elle yazılır; AI sadece fikir/veri çıkarımı için kullanılır. | |

**User's choice:** AI seed, DTCG source.
**Notes:** The user referenced `https://github.com/voltagent/awesome-design-md` and said direct brand names such as Nike, Stripe, and Apple are acceptable for references. The locked boundary is that AI may generate DTCG-compatible source tokens from those references, but canonical final manifests must still be produced by Style Dictionary.

## Sparse Theme/Variant Output

| Option | Description | Selected |
|--------|-------------|----------|
| Flat indexed output | Single themes produce `{theme}.json`; variant themes produce `{theme}.{variant}.json`; index paths are authoritative. | yes |
| Nested output | Themes and variants use nested paths such as `{theme}/{variant}.json`. | |
| Flat underscore output | Variant output uses names such as `{theme}_{variant}.json`. | |

**User's choice:** Flat indexed output.
**Notes:** The user pointed out that not every design system needs dark/light modes and that `defaultMode: "light"` is misleading for single-manifest themes. The locked model is a declared sparse theme set: single-manifest themes use `path`, variant themes use `defaultVariant` and `variants`. `light` and `dark` are variant names only, not assumptions for every theme.
